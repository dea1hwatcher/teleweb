## 2. Фаза 1 — P1, до следующего релиза

### 1.1. P1-1 — CDN203: убрать произвольный порт из `dst`

- **Файл:** `src/main.go:5099-5105`, `:5132`, `:5194-5195`.
- **Действие:** после `isCDN203IP(orig.Addr())` требовать `orig.Port() == 443`;
  для direct TCP диалить `cdn203IP:443`, а не `orig`. WSS-ветку оставить как есть
  (там уже `cdn203IP:443`).
- **Тест:** `TestCDN203RejectsNon443Port` — `handleCDN203` с
  `91.105.192.100:8080` не должен вызывать `trackedDial`; с `:443` — должен.
  Использовать существующий harness из `main_test.go:1488`.
- **Критерий:** ни один путь не строит `dst` из клиентского порта.

### 1.2. P1-2 — H2: ограничить `h2ReplySequencer.buffered`

- **Файл:** `src/cf_h2.go:177-204`, `:388-432`, `:445-547`.
- **Действие:** добавить `bufferedBytes uint64` и `maxBufferedReplies` (например,
  32 записи / 4 MiB). При превышении — `bridgeCancel()` и return error.
  Дополнительно сравнить с подходом valnesfjord `src/cf_h2.rs` (bounded window).
- **Тест:** `TestH2ReplySequencerBounded` — 100 reply с seq=1..100 при
  отсутствии seq=0 → sequencer отказывает после лимита; `TestH2ReplySequencerOrder`
  — в порядке 2,0,1 пишет 0,1,2, `nil` consume-слот.
- **Критерий:** память под Replies ограничена константой, не зависит от скорости
  клиента.

### 1.3. P1-3 — WinDivert NAT: убрать коллизию портов

- **Файл:** `src/redirect_windows.go:262-263`, `:281-296`, `:459`, `:984`, `:1057`.
- **Действие:**
  1. При старте читать dynamic port range (`netsh int ipv4 show dynamicport tcp`
     или реестр) и выбирать `natPortFirst` вне его; при ошибке — fail closed
     с явным логом.
  2. В `retLoop`/`ret6Loop` требовать совпадение полного кортежа:
     src=`127.0.0.1:defaultPort`, dst=`127.0.0.1:<natPort>` + проверка,
     что запись ещё востребована (`e.clientPort`/`clientAddr`).
- **Тест:** в `redirect_windows_test.go` — synthesize reply с чужим dport,
  Совпадающим с NAT-записью, но другим кортежем → `processRet4/6` не редактирует.
- **Критерий:** чужой loopback-трафик не переписывается ни при каком dynamic range.

### 1.4. P1-4 — GUI elevate: graceful teardown

- **Файл:** `src/win32_gui_windows.go:296-299`, `src/gui_native.go:348-352`.
- **Действие:** в `restartElevated()` перед `os.Exit(0)` вызывать
  `runShutdownHooks()`; альтернатива — передать новому процессу явный stop
  старого демона через PID-файл.
- **Тест:** юнит-тест на Windows: подменить `procShellExecute` (если возможно)
  илиintegration-чек через `TestElevateTeardown` с вызовом хука-заглушки.
- **Критерий:** после elevate не остаётся дочерний `tgws serve`, трей и mutex.

## 6. Валидация и релиз

**Перед каждым коммитом в `dev`:**

```sh
cd src
gofmt -l .
go vet ./...
go test -count=1 ./...
go test -race -count=1 ./...   # на Linux runner, без ограничений памяти
for spec in "windows amd64" "windows 386" "windows arm64" \
            "linux amd64" "linux arm64" "linux arm" "android arm64"; do
  set -- $spec
  GOOS=$1 GOARCH=$2 CGO_ENABLED=0 go build -o /dev/null . || echo "FAIL $1/$2"
done
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -tags nativegui -o /dev/null .
```

**Platform-branch rule:** на `android`/`linux` с Windows-хоста — только
`GOOS=linux go vet` + `GOOS=linux go test -c`; host `GOOS=windows` ломается
на отсутствующем Windows-слое (свойство ветки, не регресс).

**Релиз:** после completion Фаз 1–2 поднять версию до **v0.2.4** по
`docs/RELEASING.md`: `module.prop`/`update.json`/changelog в `android`,
changelog в `win`/`linux`/`master`, тег, CI release, dispatch desktop-прогонов,
проверка **14 ассетов** и скачивание модуля для сверки маркеров.

**Gate перед релизом (обязательно):**
- `git grep -nE '^\s*export\s+GOMEMLIMIT' -- '*.sh'` — пусто;
- в `status()` и `liveMetrics()` все live-поля совпадают;
- SDK/Primary-тесты из Фазы 1 зелёные на всех затронутых ветках.

## 7. Риски и открытые вопросы

1. **P1-3** требует реального Windows-стенда с расширенным dynamic port range —
   юнит-тест не заменяет проверку WinDivert-фильтра.
2. **P2-1** (Worker) — поведение detached ArrayBuffer зависит от runtime
   Cloudflare; перед выкладкой нужен smoke-тест на реальном воркере.
3. **P2-5** (GUI) проверять только `-tags nativegui` на Windows; на Linux
   эти файлы не собираются.
4. **Race-флейк** в локальном окружении мешает настаивать на «race green» —
   использовать CI runner или ограничить `-p 1` / память.
5. Все находки **не исправлены** на момент составления плана; коммит отчётов
   и `MEMORY.md` — отдельным шагом после согласования.
