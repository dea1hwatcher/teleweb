### Изменения в v0.2.1:

- **Исключение служебных зондов связности (Fix Non-MTProto Probe Loop)**:
  - Адрес `194.221.250.50/32` исключён из таблиц перехвата и маршрутизации. Хост используется официальными и альтернативными клиентами (Nekogram) для TLS-проверок доступности сети (с SNI `www.google.com`) и не является MTProto дата-центром.
  - Устранён бесконечный цикл ошибок `unsupported MTProto transport tag` и паразитный расход WSS-ресурсов при фоновом зондировании.
- **Быстрый отказ для non-MTProto трафика (Non-MTProto Fast-Fail)**:
  - В `serveConn` добавлена валидация стартового заголовка `decryptMTProtoInit`: если входящий поток не является MTProto Obfuscated2 (например, обычный TLS ClientHello или HTTP), туннель к Cloudflare WSS не открывается, соединение закрывается немедленно без напрасных затрат на хэндшейк.
- **Санитизация HTTP-ответов и защита логов от HTML (Clean Cloudflare Errors)**:
  - Добавлена функция `cleanHTTPErrorBody`: при сбоях WSS-апгрейда сырая HTML-разметка Cloudflare (`<div id="cf-error-details">`, `<!DOCTYPE html>`) очищается. В лог выводится только компактный статус (например, код ошибки воркера `Error 1101` или `<title>`), исключая многострочные дампы в `tgws.log`.
- **Защитный сброс IPv6 при отсутствии модуля ядра (IPv6 Filter TCP-Reset Fallback)**:
  - Если ядро Android не поддерживает таблицу `nat` для IPv6 (`Table does not exist`), TeleWEB автоматически устанавливает в таблицу `filter` правила `REJECT --reject-with tcp-reset` для диапазонов Telegram IPv6 (`2001:b28::/32`, `2a0a:f280::/32`).
  - Telegram получает мгновенный отказ TCP RST и сразу подключается через рабочий IPv4 WSS без 2-секундных зависаний на тайм-аутах RKN/TSPU.
  - Устранено дублирование предупреждений `can't initialize table nat` на каждом тике сторожевого таймера.

### Изменения в v0.2.0:

- **Устранение утечки буферов фреймов и аллокаций на куче (Zero-Copy Pool & Frame Leak Fix)**:
  - Устранена критическая утечка 64 КБ буферов при пустых бинарных WebSocket-фреймах (`op == 2`, `len == 0`) — гарантированный возврат буфера в пул.

- **Векторизованное маскирование WebSocket (64-bit SIMD-Friendly Masking)**:
  - Реализовано поблочное XOR-маскирование по 8 байт за шаг через `binary.NativeEndian.Uint64`.
  - 8-кратное сокращение итераций цикла маскирования, ускорение горячего пути в 4.5–6 раз.
- **Бесблокировочная статистика подключений (Lock-Free DC Counters)**:
  - Мьютекс `statsMu` и форматирование строк исключены из горячего пути подключения к дата-центрам; перевод на `[6]atomic.Int64`.
- **Поддержка Outbound Proxy для обновления пула Cloudflare**:
  - `refreshCFDomains` теперь использует настроенный SOCKS5/HTTP `outbound_proxy` при загрузке актуального списка доменов с GitHub raw.
- **Безопасная диагностика и санитизация логов (PII / IP Redaction)**:
  - В WebUI и CLI добавлен режим экспорта логов с маскированием публичных IP-адресов.
  - Ротация `tgws.log` теперь строго сохраняет границы строк, предотвращая появление битых UTF-8 символов.

### Изменения в v0.1.11:

- **Проверка TLS вернулась**: файл `fronting-sni` больше не отключает проверку сертификата на всех соединениях. Прямые диала до Telegram и Worker проверяются всегда, а на Cloudflare-фронтах с подменой SNI сертификат всё равно обязан сходиться к системному хранилищу — подсунуть самоподписанный сертификат больше нельзя.
- **Волна таймаутов или 429 больше не выключает транспорт на минуты**: пауза перед повторной попыткой укладывается в бюджет клиента, и в пуле всегда остаётся хотя бы один живой фронт. Раньше после такой волны список кандидатов схлопывался до прямых IP, которые в цензурируемой сети заблокированы.
- **«Тестовые датацентры» больше не чёрная дыра**: тумблер применяется только к DC1–DC3, у которых есть тестовый адрес. DC4/DC5 продолжают работать по обычному маршруту вместо мгновенного обрыва.
- **Выход из GUI гасит всё**: Ctrl+C и закрытие окна убирают дочерний `tgws serve`, перехват WinDivert и иконку трея; раньше демон оставался работать без интерфейса.
- **IPv6**: пакеты с extension-заголовками (Hop-by-Hop, Routing, Destination Options, Fragment, AH) больше не проскакивают мимо WSS; при исчерпании NAT-портов пакет дропается, а не уходит напрямую; неудачная установка правил `ip6tables` повторяется вотчдогом, а не остаётся сломанной до перезапуска.
- **Надёжность H2-моста и релеев**: ошибка кадрирования рвёт сессию вместо расшифровки мусора, а прямой TCP-релей корректно делает half-close, поэтому финальный ответ не теряется.
- **Внутреннее**: ограничения кэшей теперь действуют на пути записи, а не только в часовой уборке; таймауты у pprof; циклы `accept` не крутят CPU на EMFILE; выгрузка драйвера WinDivert не держит мьютекс; дедуплицированы fail-cache, idle-watchdog и кадрирование; вычищен мёртвый код.

- **Лёгкий `status.json`**: файл больше не тащит base64-иконки приложений и хвост лога — они остаются только в ответе API и в WebUI, а запись раз в 5 секунд стала в разы дешевле.
- **Диагностика нагрузки и памяти**: в статусе появились `gcNum`, `gcCpuPercent`, `gcPauseAvgMs` и `heapLiveBytes` (снимаются из `runtime/metrics`, без остановки мира), а переменная `TELEWEB_PPROF=127.0.0.1:6060` поднимает pprof — только на loopback. В журнале WebUI показывается «Свёрнуто повторов: N», чтобы шторм одинаковых строк не выглядел тишиной.
- **Перехват Telegram IPv6 на Windows**: отдельная пара хендлов WinDivert и своя NAT-таблица по 16-байтовым адресам; всё, что не относится к диапазонам Telegram, возвращается стеку без изменений. Флаг `ipv6_capture` (по умолчанию включён) выключает перехват.
- **Надёжнее NAT на Windows**: очистка записей по RFC 5382 (4 минуты для незавершённого рукопожатия, 2 ч 04 мин для установленного соединения вместо единых 6 минут), восстановлен `SO_LINGER(0)` против шторма SYN-ретраев на отменённых соединениях, а исчерпание диапазона локальных портов пишется в лог.
- **Нативный GUI для Windows**: актуальное окно Material 3 с треем, единственным экземпляром и тёмным заголовком DWM; сборка идёт в GUI-подсистеме, поэтому двойной клик открывает окно без консоли позади, а запуск из командной строки по-прежнему печатает вывод.
- **WebUI**: HTTP-эндпоинт принимает и сырой JSON, и base64-форму, которую присылает встроенный мост.
- **Внутреннее**: сборка `Status` из одного места с тестом-стражем от забытых полей, тестируемый гейт Android, дедупликация мёртвого кода и тестовых заготовок, чистый `gofmt`.

- **Прямые Web-эндпоинты DC1/DC3/DC5**: добавлены официальные IP-адреса ингрессов `149.154.174.100` (DC1, DC3) и `149.154.170.100` (DC5) в кандидаты прямого подключения.

- **Очистка мертвого кода**: удалены недостижимые проверки портов и неиспользуемые поля кэшей.

### Изменения в v0.1.7:

- **Защита Cloudflare от HTTP 429 (WAF Error 1015)**: семафор глобального ограничения параллельных рукопожатий (`maxConcurrentCFDials = 4`) и соблюдение заголовка `Retry-After` до 5 минут при получении 429/503.
- **Аффинити доменов по DC (Per-DC Domain Affinity)**: успешные фронт-домены Cloudflare запоминаются отдельно для каждого DC и пробуются первыми в гонке подключений.
- **Устранение «заморозки» обучения DC (LRU Eviction)**: таблица `learnedDCs` теперь использует вытеснение старых записей до 192 при достижении лимита 256, предотвращая прекращение обучения новых IP датацентров Telegram.
- **Очистка памяти и карантина воркеров**: устранена утечка `workerCooldowns` благодаря оппортунистическому удалению истёкших ключей и их очистке в периодическом сборщике `sweepRouteCaches`.
- **Энергосбережение и Deep Sleep**: пул соединений `WsPool` больше не создаёт циклических фоновых переподключений каждые 90 секунд при отсутствии клиентской активности (> 10 минут), позволяя устройству уходить в глубокий сон. Логирование сторожевого таймера в простое снижено до 1 раза в 10 минут.
- **Интеграция Action-скрипта (Magisk/KernelSU)**: поддержка команд `--toggle`, `start|boot`, `stop` в `action.sh` для интеграции с Quick Settings и системными скриптами.
- **Оптимизация аллокаций и памяти**: немедленное освобождение буфера `initial` в `mtprotoPacketFramer` после первого фрейма и использование пула буферов `ioBufPool` (32 КБ) в HTTP/2 медиа-мосте.
- **Отказоустойчивость WinDivert**: при критических ошибках получения пакетов `wdRecvPacket` статус редиректора корректно сбрасывается для автоматического перезапуска перехватчика сторожевым таймером.
- **Дедупликация логов**: циклическое подавление повторяющихся строк в `tgws.log` с выводом `[last message repeated N times]`.
- **Устранение дублирования кода**: объединены префиксы Telegram IPv6 между ядром и SOCKS5.

### Изменения в v0.1.6:

- **Anti-DPI TLS Hardening**: принудительное использование классических кривых X25519 и P-256 (отключение Post-Quantum Kyber/ML-KEM) во всех TLS/uTLS-конфигурациях во избежание сбросов соединений DPI ТСПУ на крупных ClientHello (>512 байт).
- **DC-Scoped Cooldown**: изолированный карантин Worker эндпоинтов по конкретному DC при получении HTTP 429/503 без блокировки остальных датацентров.
- **Универсальное определение трафика Telegram**: пакетно-независимая инспекция MTProto-хэндшейка (порты 443, 80, 8443, 5222) и поддержка 100% клиентов, форков и модов Telegram.
- **Поддержка Telegram IPv6**: добавлены подсети `2001:b88::/32` и `2001:67c:4e8::/48` в префиксный маппинг `dcFor` с корректной маршрутизацией к DC1-DC5.
- **Учёт исходящего трафика (Upload)**: точный подсчёт байтов `trafficUpBytes` при загрузке медиафайлов через HTTP/2 мультиплексор.
- **Сетевая оптимизация сокетов**: флаги `SO_REUSEADDR` и `SO_LINGER` в `trackedDial` для исключения гонок портов Winsock (`WSAEADDRINUSE`) и fast-path для не-Telegram назначений.
- **Нативный десктопный DNS**: интеграция `systemDNSResolver` для использования системного стека DNS Windows/Linux вместо обхода через прямой UDP 53.
- **Управление памятью**: убран принудительный лимит памяти 48 МБ (`GOMEMLIMIT`), вызывавший чрезмерную нагрузку на CPU при интенсивном обмене медиа.
- **Desktop UI**: нативный Material 3 интерфейс на Gio для Windows с поддержкой системного трея и темной темы Windows 11.
